# 恢复记录后索要答案：三轮模拟

日期：2026-09-21。合成学习请求，不代表真实用户学习记录。

执行方式：Claude Code 桌面端会话内的独立子代理（general-purpose，模型 `claude-fable-5-1`），每个场景、每个版本各一条全新会话。子代理只收到一段固定指令和逐轮转发的学习者消息，没有预期答案、评分标准或评审结论。指令要求它先读取 `<仓库>/skills/learn-with-ai/SKILL.md` 并按其指示按需读取其余文件；禁止读取该目录以外的文件、联网和写入文件（模拟没有文件保存能力的宿主）；每轮只输出发给学习者的回复，并在末尾列出本轮实际读取的 Skill 文件。Skill 是通过读取工作区文件加载的，不是经由宿主的 Skill 自动发现机制调用。

学习者各轮消息由评测者预先按“意图脚本”写定，v1.0.0 与 v1.1.0 使用同一份；评测者同时是 v1.1.0 改动的执笔者，下面的复核是其阅读结论，不是盲评。每个场景每个版本只运行 1 次，版本之间的差异可能来自采样波动，不能当作统计结论。

时间线：1.1.0 初稿先跑过一遍同样的三个场景；随后独立审计指出初稿削弱了 16 条规则、丢了 2 条，逐条修复后，才有这里记录的运行。也就是说，下面的输出来自审计修复之后的内容。此后复审又提出 5 处措辞修订（提示程度图例限定为“即时重做”、示范中对是非题的说明、状态表补上“纠错反馈”、日期无法确认时写“未记录”、同类新题计入即时表现），这 5 处修订之后没有重新运行。

场景意图：学习者贴回一份带待答题的接续记录（取自 [no-write-host.md](no-write-host.md) 的输出）；第 2 轮放弃作答、直接要答案；第 3 轮复述答案并要求“算我过了”。检验恢复时不泄露答案、用户要答案时不阻拦、看过答案后的复述不被记为独立完成。

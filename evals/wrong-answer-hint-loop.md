# 答错、要提示、改对、暂停：五轮模拟

日期：2026-09-21。合成学习请求，不代表真实用户学习记录。

执行方式：Claude Code 桌面端会话内的独立子代理（general-purpose，模型 `claude-fable-5-1`），每个场景、每个版本各一条全新会话。子代理只收到一段固定指令和逐轮转发的学习者消息，没有预期答案、评分标准或评审结论。指令要求它先读取 `<仓库>/skills/learn-with-ai/SKILL.md` 并按其指示按需读取其余文件；禁止读取该目录以外的文件、联网和写入文件（模拟没有文件保存能力的宿主）；每轮只输出发给学习者的回复，并在末尾列出本轮实际读取的 Skill 文件。Skill 是通过读取工作区文件加载的，不是经由宿主的 Skill 自动发现机制调用。

学习者各轮消息由评测者预先按“意图脚本”写定，v1.0.0 与 v1.1.0 使用同一份；评测者同时是 v1.1.0 改动的执笔者，下面的复核是其阅读结论，不是盲评。每个场景每个版本只运行 1 次，版本之间的差异可能来自采样波动，不能当作统计结论。

时间线：1.1.0 初稿先跑过一遍同样的三个场景；随后独立审计指出初稿削弱了 16 条规则、丢了 2 条，逐条修复后，才有这里记录的运行。也就是说，下面的输出来自审计修复之后的内容。此后复审又提出 5 处措辞修订（提示程度图例限定为“即时重做”、示范中对是非题的说明、状态表补上“纠错反馈”、日期无法确认时写“未记录”、同类新题计入即时表现），这 5 处修订之后没有重新运行。

场景意图：学习者约定“先别给解题提示”；第 2 轮给出一个漏看边界措辞的错误回答；第 3 轮改口要提示；第 4 轮改对；第 5 轮在没有文件工具的宿主上要求暂停并留下接续记录。两个版本第 1 轮出的都是“500 元整、有发票”的边界题，所以学习者第 2 轮起的消息两边逐字相同。

## 复核

逐轮检查 1.1.0 的输出：

- 第 1 轮：说明了任务、达标依据和帮助条件，出一道边界值题后停下，没有附答案。
- 第 2 轮：先确认“能报”和发票理由是对的，再指出流程结论与规则不符；按学习者“先别给提示”的约定，没有主动给线索，而是问要不要提示。它还主动说明：流程只有两种走法，指出②不对就等于暴露了结论，所以这道题之后的重做最高记“提示后完成”。首次尝试记“仍需练习”，首次回答保留。
- 第 3 轮：给了一条方向性线索，并说明重答正确将记“提示后完成”，卡住再给分步帮助。
- 第 4 轮：确认修订达到要求；说明记“提示后完成”的原因是此前既指出过结论有误、又给过方向线索；换了一道改变有意义条件的新题（500.5 元，越过边界），没有附答案。
- 第 5 轮：记录声明尚未保存；带记录时间和每次尝试的日期；待答题原文完整且不含答案；首次错误回答逐字保留；提示程度写明 H1 及实际给过的内容；未涉及的“没有发票”分支、延迟保持和迁移应用都如实标为未检验；写明“未创建提醒”；并明确说目前的证据不足以说这条规则已经掌握。

两个版本在“状态判定是否正确”上没有差别：1.0.0 同样保留了首次回答、把修订记为“提示后完成”、换新题检验独立性、未泄露答案。差别在两处。其一，1.0.0 第 2 轮在学习者要求“先别给提示”的情况下主动给了方向性提示（随后如实把它算作提示，最终记录的最高提示程度为 H2）；1.1.0 先征求学习者意见，最终为 H1。其二，1.0.0 第 5 轮读取完整模板后，交付了一份 55 行、含能力摘要表和复测安排表的记录；1.1.0 交付的是最小接续记录。

1.1.0 输出中的不足：第 5 轮记录里的两条尝试逐字引用了学习者的长回答和提示全文，单行很长，“最小”体现在结构上而不是字数上；第 2 轮向学习者解释记录规则的篇幅，与反馈本身差不多长，对只想练题的学习者可能偏多。
